# PCMN: стратегия данных и этапов обучения (v0.7)

Дата: 2026-10-19. Статус: **предложение для реализации, не результат обучения**.

## Контекст
- Репозиторий: https://github.com/msgamer000xxxyyyzzz/PCMN
- v0.6: 2.27M параметров, byte tokenizer (259); после продолжения до шага 36 NLL ~2.5613 на 7362 целевых токенах небольшого технического корпуса; синтетические exact-match задачи 0/8.
- Windows пользователь: Python 3.14.3, torch 2.14.1+cpu; `nvcc` есть, CUDA в PyTorch не доступна; проверить совместимую CUDA-сборку для Tesla P100 и CUDA-ядро до заявлений об ускорении.
- Цель: качественная универсальная языковая модель со скоростью на CPU и GPU; в перспективе кодинг, инструменты, долгие документы, многоязычность; мультимодальность позднее.

## Рекомендуемая первая смесь (экспериментальные доли токенов, НЕ установленные оптимумы)
- 32% FineWeb-Edu — английский, объяснения, разнообразные области
- 20% FineWeb2/HPLT 3.0 — русский и украинский; отдельно контролировать баланс языков
- 10% Википедия и отобранные энциклопедические документы
- 18% разрешённый и тщательно отфильтрованный код с контекстом репозиториев
- 12% FineMath и разрешённая научная/математическая литература
- 8% длинные качественные технические документы, спецификации, документация проектов

Эти проценты — отправная гипотеза. Сравнить варианты разными seed при равных токенах/параметрах; удалять точные и near-дубликаты МЕЖДУ источниками. Вместо Dolma 3 как добавки без фильтра делать альтернативный mix в отдельном эксперименте.

## Последовательность релизов
**S0. Воспроизводимая база**: Python 3.12 env, NumPy, GPU preflight отдельно, CPU/GPU numerical parity, все CI-тесты, seed/конфиг/версии.
**S1. Конвейер данных**: streaming в Parquet/JSONL.zst, языковая фильтрация и quality-score, PII/secret scanning, malware filter для кода, URL/provenance/SPDX, exact+MinHash dedup, clean train/valid/test без пересечений, реестр dataset_manifest.json.
**S2. Токенизатор**: BPE 32–64K, byte fallback, англ/рус/укр/код/LaTeX, спецтокены ролей и tools; замер fertility/bits-per-byte и lossless roundtrip.
**S3. Базовая архитектура**: 30M ablations на 50–200M токенов для сравнения скорости, памяти, NLL, BPB, multi-lang, копирования; тесты long-context и математики. 50–200M — экспериментальный инженерный бюджет, не «достаточно для качества LLM».
**S4. Первое значимое предобучение**: 100M–300M модель с 1–5B чистых токенов, подобрать по времени обучения и результатам на P100/CPU. Если GPU слишком медленно — снизить бюджет или искать доступ к более мощным ускорителям. Контрольные точки каждые N токенов; не обучать бесконечно только ради снижения train loss.
**S5. Long-context и память**: постепенное увеличение контекста 2K->8K->32K; retrieval, copy/retrieval/evidence-grounded QA, needle-in-haystack и multi-hop; проверять содержательную точность vs один лишь объём контекста.
**S6. Кодинг, математика и причинность**: продолжение предобучения на отобранных кодовых/математических примерах; SFT задачи с проверяемыми ответами; оценка компиляции, тестов, контрфактов, причинного вмешательства.
**S7. SFT диалоги и инструменты**: формат чат-ролей, строго типизированные JSON schema вызовы, аргументы, отказ, восстановление ошибки; sandbox и согласование действий по разрешениям.
**S8. Оптимизация CPU/GPU**: собственные эффективные kernels (C++/SIMD, CUDA sm_60), fused ops, FP16 на P100 (без BF16), cache, batching, quantization с метриками сохранения качества; бенчмарки prefill/decode/latency/throughput/GB.
**S9. Расширение масштаба**: только если quality-gates выполнены, 300M/1B/>1B, мультимодальные модули; обучение миллиардных моделей с нуля на имеющейся машине может быть непрактичным — определять по фактической скорости и инфраструктуре.

## Контроль качества
- Общий текст: validation NLL, perplexity, bits-per-byte, ручные RU/UK/EN тесты.
- Математика/причинность: exact-match + запуск проверяющих программ; независимые скрытые тесты и случайно генерируемые задачи, раздельная статистика.
- Код: compile rate, unit-test pass rate, repo-level repair success; HumanEval/MBPP/SWE-bench только для eval, исключать их из обучающих данных.
- Память: retrieval recall + качество ответа с цитатой и разными дистанциями / документами.
- Инструменты: exact schema parse, executable correctness, task success, refusal & permissions. Нельзя исполнять сырой код недоверенного корпуса на хосте.
- Скорость: single/batch prefill, decode t/s, first-token latency, train tokens/s, CPU RAM, GPU VRAM и энергопотребление там, где измеримо.
- Гейт перехода: улучшение контрольных метрик на независимых данных, отсутствие регрессий; не приравнивать падение NLL на мини-корпусе к уровню качественной LLM.

## Правила хранения
- Git: код, документы, configs, dataset manifests с URL+ревизией+license, тесты, отчёты и агрегированные статистики.
- Не хранить в обычном Git: сырые датасеты, PII, private keys, большие checkpoint'ы; для checkpoint — GitHub Releases/LFS либо отдельное модельное хранилище по соответствующим правилам.
- Все внешние корпуса скачать/обрабатывать только после проверки условий лицензий; публичный релиз весов обсуждать отдельно.
